# Очаг

Контур товароучёта и управленческой отчётности сети кафе. Не заменяет кассу и фискальный регистратор: продажи приходят из r_keeper 7 (сейчас — XML / Z-отчёт) или вручную, если кассовая связь выключена.

Victimok Labs.

## Что уже работает (этап 1)

- Пустая сеть по умолчанию. Первый экран — создание владельца и филиала. PIN-карточки ролей на входе нет.
- Учебная сеть для приёмки — явная кнопка «Загрузить учебную сеть» (на входе, пока сеть пустая, или в настройках у владельца). Логины примера: `owner` / `manager` / `cook` / `waiter`, пароль `ochag`.
- Четыре роли. Закрытый раздел по прямому адресу не открывается.
- Запись только в выбранный филиал. «Все филиалы» — только просмотр, без тихого Пушкина.
- Дашборд, чеки, техкарты (создание и правка), склад (приход / перемещение / списание / ревизия + акт PDF), смены с обязательным старт-листом, стоп-лист, банкеты с поиском по телефону, ФОТ при закрытии, номенклатура из CSV.
- Формулы ТЗ §5: средневзвешенная закупочная цена по складу филиала, себестоимость блюда / выход, фудкост, ожидаемая касса = размен + нал чеков, ФОТ = ставка + % с выручки смены, чистая прибыль без банкетов.
- Ручной чек выключен, пока в настройках сети включена кассовая связь с кипером (по умолчанию включена). В учебной сети связь выключена.
- PDF и CSV с сервера. Нет шрифта или ошибка сборки — сообщение на экране, не тихая заглушка.
- Сигналы: очередь outbox. Telegram / email / webpush либо уходят по ключам окружения, либо падают в журнал с текстом ошибки.

Этап 2: заявка «отправлена» + канал поставщика; история закупочных цен; закрытие периода после ревизии; сравнение двух ревизий; вечерний долг и довнесение; ведомость ФОТ со штрафами/авансами/доплатами; настраиваемые сигналы в Telegram/Web Push; PDF-комплект банкета; журнал аудита; история стоп-листа за месяц.

Этап 3: раздел «Аналитика» (ABC, план-факт, дни покрытия, отклонения) и «Очаг AI» (сводка, вопрос, рекомендации). Ollama, если доступна, иначе эвристика. Только цифры контура.

Деплой на Vercel: `vercel.json` уже в репозитории. Для production задайте `OCHAG_JWT_SECRET`. Telegram / email / VAPID / Ollama — по таблице ниже; без ключа канал пишет ошибку в очередь, не тихий успех. `DATABASE_URL` не открывайте.

Вне контура: ОФД, 1С / ЕГАИС / Меркурий, эквайринг, магазины приложений, агрегаторы, лояльность, заполнение чужих техкарт, живой `DATABASE_URL`.

## Запуск

Нужны Node 20+ и зависимости из репозитория.

```bash
npm install
npm run dev
```

Приложение слушает все интерфейсы на порту 8080. База не нужна: снимок в памяти процесса, по умолчанию пустой.

Полезные команды: `npm run typecheck`, `npm test`, `npm run build`.

### JSON вместо памяти

```bash
OCHAG_STORE=json npm run dev
```

Снимок пишется в `.data/ochag.json` (каталог в gitignore). На хостинге без диска оставьте память.

## Postgres позже

Миграции:

- `migrations/0002_ops.sql` — старый JSON-снимок (совместимость).
- `migrations/0003_core.sql` — нормализованная схема этапа 1.

`DATABASE_URL` **специально не открывается**. Когда будете готовы:

1. Поднять PostgreSQL 16 и прогнать миграции (`npm run db:migrate` уже умеет каталог `migrations/`).
2. Реализовать `src/lib/repo/postgres.ts` (заготовка бросает понятную ошибку).
3. Включить `OCHAG_STORE=postgres`.

До этого живой Neon / чужой хостинг не подключайте. PIN в открытом виде — до Postgres.

## Окружение (без `.env` в репозитории)

| Переменная | Зачем |
| --- | --- |
| `OCHAG_JWT_SECRET` | Обязателен в production (`OCHAG_ENV` / `NODE_ENV` / `VERCEL_ENV`). В dev — встроенный секрет. |
| `OCHAG_TELEGRAM_BOT_TOKEN` + `OCHAG_TELEGRAM_CHAT_ID` | Отправка из outbox в Telegram. Нет ключей — запись `failed` с текстом. |
| `OCHAG_EMAIL_WEBHOOK` | POST `{ to, subject, text }`. |
| `OCHAG_VAPID_PUBLIC` + `OCHAG_VAPID_PRIVATE` | Web Push: подписка сохраняется, отправка ждёт адаптер (ошибка в очереди, не тишина). |
| `OLLAMA_BASE_URL` / `OLLAMA_MODEL` | AI. По умолчанию `http://127.0.0.1:11434` и `llama3.2`. Нет Ollama — эвристика. |
| `OCHAG_STORE` | `memory` (по умолчанию) или `json`. |

## REST

Префикс `/api/v1`. Примеры:

- `GET /api/v1/health` — `onboarded`, `notify`, `store`
- `POST /api/v1/auth/onboard` — первая сеть
- `POST /api/v1/auth/login` `{ login, password }`
- `POST /api/v1/auth/pin` `{ login, pin }`
- `POST /api/v1/state/sample` — учебная сеть (без входа, только пока сеть пустая; иначе владелец)
- `GET /api/v1/state` (Bearer JWT)
- `POST /api/v1/sales/keeper-xml` `{ xml }`
- `GET /api/v1/reports/pdf` · `reports/csv`
- `POST /api/v1/notify/flush`

Пример XML: `public/samples/keeper-zreport.xml`.
