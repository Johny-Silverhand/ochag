# Очаг

Контур товароучёта и управленческой отчётности сети кафе. Не заменяет кассу и фискальный регистратор: продажи приходят из r_keeper 7 (сейчас — заглушка XML / Z-отчёта) или вручную.

Victimok Labs.

## Что уже работает (этап 1)

- Четыре роли: владелец, управляющий, повар, официант. Права и филиал проверяются на сервере.
- Вход: логин + пароль **или** логин + PIN. Сервер выдаёт JWT.
- Дашборды, чеки, техкарты, склад (приход / перемещение / списание / ревизия), смены с ожидаемой кассой, стоп- и старт-лист, банкеты, ФОТ при закрытии смены, постоянные расходы.
- Формулы ТЗ §5: средневзвешенная закупочная цена, себестоимость блюда, фудкост, ожидаемая касса, ФОТ, чистая прибыль. `cost_at_sale` замораживается в чеке.
- Этап 2: каркасы «План», «График», «Качество».
- Этап 3: раздел AI (Ollama или эвристика).

Вне контура: ОФД, 1С / ЕГАИС / Меркурий, эквайринг, магазины приложений, агрегаторы доставки, маркетинг / лояльность, заполнение чужих техкарт, живой хостинг Postgres.

## Запуск

Нужны Node 20+ и зависимости из репозитория.

```bash
npm install
npm run dev
```

Приложение слушает все интерфейсы на порту 8080. База не нужна: по умолчанию живой снимок сети лежит в памяти процесса (демо-данные «Очаг»).

Демо-вход (пароль у всех `ochag`):

| Роль        | Логин   | PIN  |
| ----------- | ------- | ---- |
| Владелец    | owner   | 1001 |
| Управляющий | manager | 2001 |
| Повар       | cook    | 3001 |
| Официант    | waiter  | 4001 |

Сброс демо — в «Интеграции» (владелец / управляющий).

Полезные команды: `npm run typecheck`, `npm test`, `npm run build`.

### JSON вместо памяти

```bash
OCHAG_STORE=json npm run dev
```

Снимок пишется в `.data/ochag.json` (каталог в gitignore). На хостинге без диска оставьте память.

## Postgres позже

Миграции:

- `migrations/0002_ops.sql` — старый JSON-снимок (совместимость).
- `migrations/0003_core.sql` — нормализованная схема этапа 1.

`DATABASE_URL` **специально не открывается**. Когда будете готовы:

1. Поднять PostgreSQL 16 и прогнать миграции (`npm run db:migrate` уже умеет каталог `migrations/`).
2. Реализовать `src/lib/repo/postgres.ts` (заготовка бросает понятную ошибку).
3. Включить `OCHAG_STORE=postgres`.

До этого живой Neon / чужой хостинг не подключайте.

## Ollama (локальный AI)

Раздел «AI» ходит в OpenAI-совместимый HTTP. Если Ollama не запущена, отвечает эвристика по тем же агрегатам.

```bash
# пример
ollama serve
ollama pull llama3.2
```

Переменные (без `.env` в репозитории — задайте в оболочке):

| Переменная         | По умолчанию                  |
| ------------------ | ----------------------------- |
| `OLLAMA_BASE_URL`  | `http://127.0.0.1:11434`      |
| `OLLAMA_MODEL`     | `llama3.2`                    |
| `OCHAG_JWT_SECRET` | dev-секрет, смените на проде  |

В модель уходят только агрегаты: выручка, фудкост, списания, ФОТ, топ блюд, стоп-лист. Без телефонов, PIN и сырых чеков.

## REST

Префикс `/api/v1`. Примеры:

- `GET /api/v1/health`
- `POST /api/v1/auth/login` `{ login, password }`
- `POST /api/v1/auth/pin` `{ login, pin }`
- `GET /api/v1/state` (Bearer JWT)
- `POST /api/v1/sales/keeper-xml` `{ xml }`
- `POST /api/v1/sales/z-report` `{ receipts }`
- `POST /api/v1/stock/transfer`
- `POST /api/v1/ai/narrative` · `ai/ask` · `ai/recommend`
- `POST /api/v1/notify/telegram` и `notify/push` — заглушки
- `GET /api/v1/reports/pdf` — заглушка (CSV на странице «Отчёты» настоящий)

Пример XML: `public/samples/keeper-zreport.xml`.

## Стек

Vite + React + TypeScript (оболочка, которая уже была). Серверные функции и `/api/v1` на том же процессе. JWT (`jose`). Репозиторий в памяти / JSON. PostgreSQL подготовлен, не подключён.
