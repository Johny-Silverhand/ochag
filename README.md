# RestoPro

Контур товароучёта и управленческой отчётности сети кафе. Не заменяет кассу и фискальный регистратор: продажи приходят из r_keeper 7 (сейчас — XML / Z-отчёт) или вручную, если кассовая связь выключена.

Имя в интерфейсе — **RestoPro**. Репозиторий и переменные окружения (`OCHAG_*`, строка `ops_state`) остаются `ochag`, чтобы не сбросить живой Neon.

## Что уже работает (этап 1)

- Публичный экран: «Что это?», «Выбрать тариф», симуляция оплаты, затем «Создать сеть» (владелец + первый филиал). Выданный логин по-прежнему входит паролем или PIN — публичной регистрации без оплаты нет.
- Первый администратор-техник: `POST /api/v1/auth/bootstrap` (токен) или вставка в учебный leftover-снимок из `OCHAG_BOOTSTRAP_*`. Пустой снимок env-bootstrap больше не занимает — иначе не открылся бы коммерческий онбординг. Дальше учётки создают в админке «Пользователи»: логин, пароль и PIN показывают один раз. У техника также «Консоль» и «Журнал».
- Пять ролей: администратор-техник (полный доступ ко всем разделам и филиалам), владелец, управляющий, повар, официант. Закрытый раздел по прямому адресу не открывается.
- Учебная сеть для приёмки — не на экране входа. QA: `POST /api/v1/state/sample` (пока сеть пустая) или кнопка в настройках у администратора-техника / владельца. Логины примера: `admin` (техник) / `owner` / `manager` / `cook` / `waiter`, пароль `ochag`.
- Запись только в выбранный филиал. «Все филиалы» — только просмотр, без тихого Пушкина.
- Дашборд, чеки, техкарты (создание и правка), склад (приход / перемещение / списание / ревизия + акт PDF), смены с обязательным старт-листом, стоп-лист, банкеты с поиском по телефону, ФОТ при закрытии, номенклатура из CSV.
- Формулы ТЗ §5: средневзвешенная закупочная цена по складу филиала, себестоимость блюда / выход, фудкост, ожидаемая касса = размен + нал чеков, ФОТ = ставка + % с выручки смены, чистая прибыль без банкетов.
- Ручной чек выключен, пока в настройках сети включена кассовая связь с кипером (по умолчанию включена). В учебной сети связь выключена.
- PDF и CSV с сервера. Нет шрифта или ошибка сборки — сообщение на экране, не тихая заглушка.
- Сигналы: очередь outbox. Telegram / email / webpush либо уходят по ключам окружения, либо падают в журнал с текстом ошибки.

Этап 2: заявка «отправлена» + канал поставщика; история закупочных цен; закрытие периода после ревизии; сравнение двух ревизий; вечерний долг и довнесение; ведомость ФОТ со штрафами/авансами/доплатами; настраиваемые сигналы в Telegram/Web Push; PDF-комплект банкета; журнал аудита; история стоп-листа за месяц.

Этап 3: раздел «Аналитика» (ABC, план-факт, дни покрытия, отклонения) и «RestoPro AI» — сводка, рекомендации, маржа, прогноз месяца, пики смен и покрытие склада. Те же расчёты вызываются с экранов аналитики и отчётов. Живая Ollama, если владелец указал адрес; иначе честная эвристика по формулам. Свободного чата нет. PIN и телефоны в модель не уходят. Как поднять Ollama — `docs/ollama.md`.

Wave 2: долги учёта (только владелец), хозы, побочные расходы смены, фотоотчёты на приходе и ревизии, премии ФОТ, средний чек и выручка по часам, отмены/скидки по официантам.

Необязательный хвост этапа 3, который уже в контуре: вкладка ТТК у техкарты и PDF внутренней накладной на перемещении. Справочник RK7 `GetRefData` по кодам блюд — нет, стыковка по имени.

Техник переключает **контур владельца** и филиалы без повторного входа. Несколько устройств на одном логине, отзыв сессии в настройках. Безопасность: `docs/security.md`.

Деплой на Vercel: боевой адрес — **https://restopro.vercel.app** (прежние алиасы https://restopro-theta.vercel.app и https://ochag-theta.vercel.app ещё живы). `vercel.json` уже в репозитории. Задайте `OCHAG_JWT_SECRET` в Environment Variables для **Production и Preview** (у Preview тоже `NODE_ENV=production` — без секрета `POST /api/v1/auth/login` и `auth/pin` отвечают ошибкой). Пустая сеть: тариф → симуляция оплаты → «Создать сеть». Выданные учётки входят как раньше. Telegram / email / VAPID / Ollama — по таблице ниже; без ключа канал пишет ошибку в очередь, не тихий успех. Для постоянных учёток нужен `DATABASE_URL` (Neon): при его наличии хранилище само переключается на Postgres.

Вне контура: ОФД, 1С / ЕГАИС / Меркурий, эквайринг, магазины приложений, агрегаторы, лояльность, заполнение чужих техкарт.

## Запуск

Нужны Node 20+ и зависимости из репозитория.

```bash
npm install
npm run dev
```

Приложение слушает все интерфейсы на порту 8080. Без `DATABASE_URL` снимок в памяти процесса, по умолчанию пустой. Пока нет пользователей: «Что это?», тарифы и симуляция оплаты; «Создать сеть» появляется только после симуляции.

### Тарифы и онбординг

Четыре тарифа (пробный, базовый, средний, профессиональный + ИИ). Оплата на экране входа проходит внутри контура, без внешнего эквайринга; в снимке пишутся `settings.tariff` и `settings.paymentSimulatedAt`. Пока нет администратора-техника, «Создать сеть» доступна после оплаты только на пустом (или учебном leftover) снимке. Если техник уже есть, каждый новый «Создать сеть» **добавляет** владельца и первый филиал — остальных не стирает. Тариф и отметка оплаты пока **глобальные** на одном документе `ops_state` (не per-сеть). Выданный логин работает независимо. Администратор-техник в «Пользователи» видит все учётки.

### Первый администратор-техник

Env-bootstrap **не** создаёт техника на пустом снимке (это место занимает коммерческий онбординг). Если в leftover-учебной сети нет техника и заданы три переменные, запрос к API *добавляет* администратора-техника, сеть не стирается.

```bash
OCHAG_BOOTSTRAP_LOGIN=admin \
OCHAG_BOOTSTRAP_PASSWORD='замените' \
OCHAG_BOOTSTRAP_PIN=1001 \
npm run dev
```

Опционально: `OCHAG_BOOTSTRAP_NAME`, `OCHAG_BOOTSTRAP_BRANCH`, `OCHAG_BOOTSTRAP_CITY`, `OCHAG_BOOTSTRAP_ADDRESS`.

Либо одноразовый `POST /api/v1/auth/bootstrap` с тем же телом (`login`, `password`, `pin`, …) и заголовком `x-ochag-bootstrap` / полем `token`, если задан `OCHAG_BOOTSTRAP_TOKEN`. Без токена этот маршрут отвечает 403. Повторно, когда пользователи уже есть, — 400. После симуляции оплаты, пока сеть не создана, env-bootstrap пропускается.

Дальше владелец и остальные сотрудники создаются в разделе «Пользователи» (или владелец — через «Создать сеть» после тарифа). Администратор-техник может выдать любую роль, включая владельца и другого техника. Пароль и PIN показывают один раз. Консоль и журнал — только у техника.

Полезные команды: `npm run typecheck`, `npm test`, `npm run build`.

### JSON вместо памяти (только локально)

```bash
OCHAG_STORE=json npm run dev
```

Снимок пишется в `.data/ochag.json` (каталог в gitignore). На Vercel диска нет — нужен Postgres.

## Postgres (прод)

Миграции:

- `migrations/0002_ops.sql` — JSON-снимок сети в `ops_state` (рабочее хранилище).
- `migrations/0003_core.sql` — нормализованная схема на потом; контур пока пишет документ целиком.

Если задан `DATABASE_URL`, `OCHAG_STORE` можно не трогать: включается Postgres (`neon`). Явно: `OCHAG_STORE=postgres`. Сборка прогоняет `npm run db:migrate`. PIN и пароль по-прежнему в снимке, пока нет отдельной схемы учёток.

`OCHAG_STORE=memory` на Vercel снова теряет учётки на холодном старте — так не деплойте.

## Окружение (без `.env` в репозитории)

| Переменная | Зачем |
| --- | --- |
| `OCHAG_JWT_SECRET` | Обязателен на Vercel **Production и Preview** (`OCHAG_ENV` / `NODE_ENV` / `VERCEL_ENV=production`). В локальном dev — встроенный секрет. |
| `DATABASE_URL` | Neon / Postgres. Если задан — постоянный снимок сети (учётки, смены, чеки). |
| `OCHAG_STORE` | Пусто: `neon` при `DATABASE_URL`, иначе `memory`. Ещё: `json`, `memory`, `postgres`. |
| `OCHAG_TELEGRAM_BOT_TOKEN` + `OCHAG_TELEGRAM_CHAT_ID` | Отправка из outbox в Telegram. Нет ключей — запись `failed` с текстом. |
| `OCHAG_EMAIL_WEBHOOK` | POST `{ to, subject, text }`. |
| `OCHAG_VAPID_PUBLIC` + `OCHAG_VAPID_PRIVATE` | Web Push: подписка сохраняется, отправка ждёт адаптер (ошибка в очереди, не тишина). |
| `OLLAMA_BASE_URL` / `OLLAMA_MODEL` | Запасной адрес локальной Ollama, если в настройках сети выключатель не выключен. По умолчанию модель не вызывается, пока владелец не включит её. С Vercel нужен публичный туннель до кафе, не `127.0.0.1`. См. `docs/ollama.md`. |
| `OCHAG_BOOTSTRAP_LOGIN` + `OCHAG_BOOTSTRAP_PASSWORD` + `OCHAG_BOOTSTRAP_PIN` | Вставка техника в leftover-учебную сеть без техника. Пустой снимок не занимает. |
| `OCHAG_BOOTSTRAP_TOKEN` | Секрет для `POST /api/v1/auth/bootstrap`. Без токена маршрут выключен. |
| `OCHAG_KEEPER_URL` | HTTP XML-интерфейса RK7. Пусто — только загрузка файла. С Vercel касса в локальной сети кафе обычно недоступна. |
| `OCHAG_KEEPER_USER` / `OCHAG_KEEPER_PASSWORD` | Basic auth XML-учётки. |
| `OCHAG_KEEPER_TERMINAL` | Код кассы в GetOrderList. |
| `OCHAG_KEEPER_QUERY` | Свой XML-запрос вместо GetOrderList. |

Пошаговая инструкция для кафе — в приложении: Интеграции → Кипер.

## REST

Префикс `/api/v1`. Примеры:

- `GET /api/v1/health` — `onboarded`, `notify`, `store`, `billing`
- `GET /api/v1/billing` — тариф, симуляция оплаты, можно ли «Создать сеть»
- `POST /api/v1/billing/simulate` `{ tariff }` — всегда успех, пишет тариф
- `POST /api/v1/auth/bootstrap` — первый администратор-техник (пустое хранилище + `OCHAG_BOOTSTRAP_TOKEN`)
- `POST /api/v1/auth/onboard` — после симуляции оплаты, пока пользователей нет
- `POST /api/v1/auth/login` `{ login, password }`
- `POST /api/v1/auth/pin` `{ login, pin }`
- `POST /api/v1/state/sample` — учебная сеть для QA (без входа, только пока сеть пустая; иначе администратор-техник / владелец)
- `GET /api/v1/state` (Bearer JWT)
- `GET /api/v1/integrations/keeper` — статус XML/HTTP кипера
- `POST /api/v1/sales/keeper-xml` `{ xml }`
- `POST /api/v1/sales/keeper-pull` — HTTP к RK7, если задан `OCHAG_KEEPER_URL`
- `GET /api/v1/reports/pdf` · `reports/csv`
- `POST /api/v1/notify/flush`

Пример XML: `public/samples/keeper-zreport.xml`.

## Стек

Vite + React + TypeScript (оболочка, которая уже была). Серверные функции и `/api/v1` на том же процессе. JWT (`jose`). Репозиторий: память / JSON / Postgres (`ops_state` JSONB).
